# Первый сайт на Django — список задач

Здесь можно добавить задачу, отметить её выполненной, вернуть обратно и удалить.
Всё работает на Python и обычном HTML, без JavaScript. База SQLite — один файл.

## Запуск на Windows

Нужен Python 3.10 или новее. Открой терминал в папке с этим README и manage.py.
Выполни команды по очереди:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Открой http://127.0.0.1:8000/ в браузере. Терминал должен оставаться открытым.
Остановка сервера: Ctrl+C. Для следующего запуска нужна только последняя команда.
Активация окружения не нужна: мы явно указываем путь к его Python.
Если порт занят: добавь `8001` после `runserver` и открой адрес с портом 8001.

`venv` создаёт отдельное место для библиотек проекта. `pip install` устанавливает
Django. `migrate` создаёт таблицу задач. `runserver` запускает локальный сервер.

## Как всё связано

Представь, что браузер отправляет письмо серверу. В письме есть адрес и иногда данные.

```text
Браузер → config/urls.py → tasks/urls.py → tasks/views.py
                                            ↓
                                      tasks/models.py ↔ SQLite
                                            ↓
                                templates/tasks/index.html → браузер
```

Читай файлы в таком порядке:

1. `tasks/urls.py` — какой адрес вызывает какую функцию. Пустая строка означает главную страницу `/`.
2. `tasks/views.py` — что делать с запросом. `index` показывает страницу и принимает новые задачи.
3. `tasks/models.py` — какие данные храним. `Task` описывает задачу: текст `title` и флаг `done`.
4. `tasks/forms.py` — как проверять введённый текст. Пустой текст и строки длиннее 200 символов не пройдут проверку.
5. `tasks/templates/tasks/index.html` — как выглядит ответ. CSS в `<style>` отвечает только за оформление.
6. `config/settings.py` — настройки всего проекта и путь к базе данных.

`config` — общие настройки сайта. `tasks` — одно приложение внутри сайта.
Например, у магазина могли бы быть приложения `products`, `orders`, `users`.

## Проследи одно нажатие «Добавить»

1. Браузер отправляет POST на `/`. В запросе находится поле `title`.
2. Django находит `index` через таблицу адресов.
3. `TaskForm(request.POST)` берёт введённые данные.
4. `form.is_valid()` проверяет их. Если есть ошибка, страница показывает её.
5. `form.save()` создаёт строку в базе. SQL писать не приходится: этим занимается Django.
6. `redirect` отправляет браузер снова открыть `/` методом GET.
7. `Task.objects.order_by('-id')` читает задачи, новые сверху.
8. `render` подставляет задачи в HTML и возвращает страницу браузеру.

GET обычно означает «покажи», POST — «приними данные».
`pk` в адресе — номер записи в базе. Для `/tasks/3/toggle/` это задача с номером 3.
`get_object_or_404` вернёт страницу 404, если такого номера нет.

В шаблоне `{{ task.title }}` выводит значение, `{% for ... %}` повторяет HTML,
`{% if ... %}` выбирает вариант. Django экранирует текст задачи при выводе.
`{% csrf_token %}` нужен внутри каждой POST-формы для защиты от подделки запросов.

## Попробуй сам

1. Измени заголовок `<h1>` в HTML и обнови страницу.
2. Измени цвет `background` у `body`.
3. Замени `order_by('-id')` на `order_by('id')`: старые задачи окажутся сверху.
4. Добавь поле `description = models.TextField(blank=True)` в модель.
   Затем выполни `manage.py makemigrations` и `manage.py migrate` через Python окружения.
   Чтобы вводить описание, добавь его в `fields` формы и выведи поле в шаблоне.

При изменении структуры модели нужны миграции. При изменении текста или CSS — нет.
Начальная миграция уже включена в проект, поэтому при первом запуске достаточно `migrate`.

## Проверка

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
```

Тесты проверяют создание, валидацию, переключение, удаление и защиту POST-запросов.

Это локальный учебный сайт с общим списком без регистрации. Перед размещением в интернете
нужны настройки production, секретный ключ вне кода и разграничение доступа.
`runserver` предназначен для разработки.

Дальше можно пройти официальный учебник: https://docs.djangoproject.com/en/5.2/intro/tutorial01/
