# Django на прикладі цього проєкту

## 1. Що таке Django

Django це **фреймворк для сайтів на Python**. Він дає готовий каркас: приймає запити з браузера, працює з базою, віддає HTML. Залишається писати тільки свою логіку.

Приклад: ти відкриваєш кафе. Можна самому будувати кухню, зал і касу. Django це готове приміщення з обладнанням, а ти тільки вирішуєш, що в меню.

## 2. Головна ідея: запит → відповідь

```
Браузер питає: "дай сторінку /"  →  Django щось робить  →  віддає HTML
```

Усі файли проєкту обслуговують цей ланцюжок.

## 3. Шлях запиту крок за кроком

```
Браузер
   ↓  запит на адресу /
config/urls.py        ← "кому передати цей адрес?"
   ↓
tasks/urls.py         ← "яка саме вьюшка?"
   ↓
tasks/views.py        ← "що робити?" (логіка)
   ↓  ↑
tasks/models.py ↔ db.sqlite3     ← дані з бази
   ↓
templates/tasks/index.html       ← малюємо HTML
   ↓
Браузер отримує сторінку
```

## 4. Проєкт і застосунок: `config` та `tasks`

- **`config/`** це налаштування всього сайту: `settings.py`, головні адреси, запуск.
- **`tasks/`** це один застосунок (app) всередині сайту з усією логікою завдань.

Приклад з інтернет-магазином: проєкт один, а застосунків кілька (`products`, `orders`, `users`). Кожен відповідає за свою частину. Тут поки один: `tasks`.

**`manage.py`** це пульт керування: `python manage.py <команда>` запускає сервер, міграції й тести.

## 5. `urls.py` — «телефонна книга»

```python
path("", views.index, name="index"),
path("tasks/<int:pk>/toggle/", views.toggle, name="toggle"),
path("tasks/<int:pk>/delete/", views.delete, name="delete"),
```

| Адреса в браузері | Яка функція викликається |
|---|---|
| `/` | `views.index` |
| `/tasks/3/toggle/` | `views.toggle` (з `pk=3`) |
| `/tasks/3/delete/` | `views.delete` (з `pk=3`) |

- `""` означає головну сторінку.
- `<int:pk>` це змінна частина адреси. Django бере число з URL і передає у функцію як `pk` (primary key, номер запису в базі).
- `name="index"` це ім'я адреси. За ним на адресу посилаються з коду й шаблонів (`{% url 'tasks:index' %}`). Якщо адреса зміниться, нічого не зламається.
- `app_name = "tasks"` це простір імен, тому пишемо `tasks:index`.

`config/urls.py` каже: «усе, що не моє, віддай у `tasks/urls.py`».

## 6. `models.py` — як зберігаються дані

```python
class Task(models.Model):
    title = models.CharField("Задача", max_length=200)
    done = models.BooleanField("Выполнена", default=False)
```

**Модель це опис таблиці в базі, записаний як Python-клас.**

- Клас `Task` це таблиця «задачі».
- `title` і `done` це колонки: текст до 200 символів і прапорець «зроблено» (за замовчуванням ні).
- Один об'єкт `Task` це один рядок таблиці.

**SQL писати не треба:**

```python
Task.objects.create(title="Купити хліб")     # додати рядок
Task.objects.all()                            # прочитати всі
Task.objects.order_by("-id")                  # відсортувати, нові зверху
task.delete()                                 # видалити
```

Цей шар називається **ORM**: він перекладає Python у SQL. База SQLite це один файл `db.sqlite3`, окремий сервер не потрібен.

### Міграції

Якщо змінити модель (додати поле), у базі колонки ще немає. Для цього є міграції:

1. `makemigrations` Django дивиться на зміни в моделях і пише файл-інструкцію (`migrations/0001_initial.py`).
2. `migrate` Django виконує інструкції й змінює базу.

Міграції це «git для структури бази». Змінив модель: `makemigrations`, потім `migrate`. Змінив HTML чи CSS: нічого робити не треба.

## 7. `views.py` — мозок

Вьюха це **функція, яка приймає запит і повертає відповідь.**

```python
def index(request):
    if request.method == "POST":            # користувач натиснув "Додати"
        form = TaskForm(request.POST)       # беремо введені дані
        if form.is_valid():                 # перевіряємо
            form.save()                     # зберігаємо в базу
            return redirect("tasks:index")  # відправляємо на / заново
    else:                                   # просто відкрили сторінку
        form = TaskForm()

    tasks = Task.objects.order_by("-id")
    return render(request, "tasks/index.html", {"tasks": tasks, "form": form})
```

- **`request`** це все про запит: метод, введені дані, куки.
- **GET** означає «покажи сторінку». **POST** означає «прийми дані» (відправка форми).
- **`render(...)`** бере шаблон і підставляє в нього дані. Словник `{"tasks": ..., "form": ...}` це контекст: те, що в ньому лежить, доступне шаблону.
- **`redirect`** каже браузеру: «іди на цю адресу ще раз». Завдяки цьому F5 після додавання не відправить форму вдруге й не створить дублікат. Підхід називається **Post/Redirect/Get**.

Інші дві вьюхи:

```python
@require_POST
def toggle(request, pk):
    task = get_object_or_404(Task, pk=pk)   # знайти задачу або показати 404
    task.done = not task.done               # перемкнути
    task.save(update_fields=["done"])       # зберегти тільки це поле
    return redirect("tasks:index")
```

- **`@require_POST`** це декоратор: пускає сюди тільки POST. Зміна даних через GET небезпечна, бо пошуковик чи плагін браузера може пройти по посиланнях і видалити все.
- **`get_object_or_404`**: якщо задачі з таким номером немає, користувач бачить сторінку 404, а не помилку сервера.

## 8. `forms.py` — перевірка введеного

Користувачу не можна вірити: він може відправити порожній рядок або текст на 5000 символів.

```python
class TaskForm(forms.ModelForm):
    class Meta:
        model = Task
        fields = ["title"]
```

**ModelForm** сам дивиться на модель `Task` і будує форму з правилами:

- Поле обов'язкове, не порожнє.
- Не більше 200 символів (бере з `max_length`).
- Пробіли по краях обрізаються, тому рядок із самих пробілів вважається порожнім.

Методи:

- `form.is_valid()` перевіряє введене.
- `form.errors` містить помилки, які шаблон покаже користувачу.
- `form.save()` створює запис у базі.

`widgets` змінює лише вигляд поля (плейсхолдер, вимкнене автозаповнення).

## 9. Шаблон `index.html` — HTML з «дірками»

Звичайний HTML, куди Django підставляє дані. Мова шаблонів:

| Синтаксис | Що робить |
|---|---|
| `{{ task.title }}` | вивести значення |
| `{% for task in tasks %} ... {% endfor %}` | повторити блок для кожної задачі |
| `{% empty %}` | що показати, якщо список порожній |
| `{% if task.done %} ... {% else %} ... {% endif %}` | умова |
| `{% url 'tasks:toggle' task.pk %}` | побудувати адресу за іменем |
| `{% csrf_token %}` | захисний токен у формі |
| `{# коментар #}` | коментар, у HTML не потрапляє |

**Автоматичне екранування:** якщо хтось додасть задачу `<script>alert(1)</script>`, Django виведе її як безпечний текст і не виконає. Це захист від XSS.

**CSRF-токен:** уяви, що ти залогінений у банку, а шкідливий сайт приховано відправляє форму «переказ грошей» від твого імені. CSRF-токен це секретний код, який є тільки в справжній формі твого сайту. Запит без нього Django відхиляє з помилкою 403. Тому токен потрібен у кожній POST-формі.

Кнопки «Готово» і «Видалити» це маленькі форми. Кожна відправляє POST на свою адресу з номером задачі.

## 10. `settings.py` — налаштування

- `DEBUG = True` показує докладні помилки. Локально зручно, в інтернеті небезпечно.
- `SECRET_KEY` це секретний ключ для підписів і безпеки. Тут він навчальний. Для реального сайту його зберігають поза кодом.
- `ALLOWED_HOSTS` це з яких доменів сайт відповідає.
- `INSTALLED_APPS = ["tasks"]` це список підключених застосунків. Новий застосунок додається сюди.
- `MIDDLEWARE` це «прохідна»: кожен запит проходить через ці шари перед вьюхою (безпека, CSRF-перевірка тощо).
- `DATABASES` це де лежить база (тут файл `db.sqlite3`).
- `TEMPLATES` це де шукати шаблони. `APP_DIRS: True` означає «у папках `templates/` кожного застосунку».
- `LANGUAGE_CODE = "ru"` це мова службових повідомлень Django.

## 11. Тести

`tests.py` це код, який сам перевіряє, що сайт працює. `self.client` це «віртуальний браузер»: він ходить по сайту без справжнього сервера. Для тестів створюється окрема тимчасова база, реальні дані не чіпаються. Запуск: `manage.py test`.

Перевіряється: створення, перемикання й видалення задачі, відсікання поганого вводу, 404, заборона GET там, де потрібен POST, CSRF, екранування HTML.

## 12. Повний шлях натискання «Додати»

1. Користувач пише «Купити молоко» і тисне кнопку. Браузер шле **POST на `/`** з `title=Купити молоко` і CSRF-токеном.
2. Django перевіряє токен (middleware) і шукає адресу в `urls.py`.
3. Викликається `index(request)`. Метод POST, тому створюється `TaskForm(request.POST)`.
4. `is_valid()` каже «ок». `form.save()` додає рядок у `db.sqlite3`.
5. `redirect` повертає браузеру: «іди на `/`».
6. Браузер робить **GET на `/`**. `index` зчитує задачі з бази й викликає `render`.
7. Шаблон будує HTML зі списком. Нова задача зверху, бо сортування `-id` означає «від більшого id до меншого».

## 13. Як запустити й що пробувати

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Відкрий http://127.0.0.1:8000/. Вправи:

1. Зміни текст `<h1>` у `index.html`, онови сторінку й побачиш результат одразу.
2. Заміни `order_by("-id")` на `order_by("id")`: старі задачі будуть зверху.
3. Додай поле `description = models.TextField(blank=True)` у модель, виконай `makemigrations` і `migrate`, додай поле у `fields` форми й виведи в шаблоні.

## 14. Шпаргалка

| Що | Де | Одним реченням |
|---|---|---|
| URLs | `urls.py` | адреса → функція |
| View | `views.py` | функція, що обробляє запит |
| Model | `models.py` | таблиця в базі як Python-клас |
| Form | `forms.py` | перевірка й збереження введеного |
| Template | `templates/*.html` | HTML з підстановками |
| Settings | `settings.py` | налаштування сайту |
| Migration | `migrations/` | інструкція зміни бази |
| ORM | `Task.objects...` | робота з базою без SQL |

Django часто описують скороченням **MTV** (Model, Template, View): дані, вигляд і логіка лежать окремо. Тому в проєкті стільки файлів, і кожен робить одну справу.
